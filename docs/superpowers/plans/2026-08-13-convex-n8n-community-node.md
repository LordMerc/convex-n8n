# Convex n8n Community Node Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a publishable `@lordmerc/n8n-nodes-convex` v0.1.0 package with isolated application and Team API credentials, a Convex function/HTTP Action node, and a read-only Convex Platform node.

**Architecture:** Follow the current `@n8n/node-cli` starter and declarative routing model. Keep request validation, origin enforcement, response normalization, error mapping, and cursor safety in small exported helpers that routing hooks call and unit tests exercise without live credentials. Keep application and Team Access Tokens in distinct credential types and hardcode the Team API origin.

**Tech Stack:** Node.js 22.22+, TypeScript 5.9, `@n8n/node-cli`, `n8n-workflow`, ESLint 9, Prettier 3, Node's built-in test runner, npm, GitHub Actions.

- Package name is exactly `@lordmerc/n8n-nodes-convex`; initial version is exactly `0.1.0`.
- Author is Mike Boyd and license is MIT.
- Node.js engine is `>=22.22.0`; `n8nNodesApiVersion` is `1`; n8n strict mode is enabled.

- Use application bearer tokens only for the Convex node and Team Access Tokens only for `https://api.convex.dev/v1`.
- Convex Platform operations remain read-only.
- Custom HTTP Actions remain JSON-only, same-origin, non-redirecting, and cannot override security-sensitive headers.
- Do not add automatic retries to any operation.

- [ ] **Step 3: Implement strict JSON-object parsing and output normalization**

```ts
export function parseJsonObject(value: unknown, fieldName: string): IDataObject {
	let parsed = value;
	if (typeof value === 'string') {
		try {
			parsed = JSON.parse(value);
		} catch {
			throw new Error(`${fieldName} must be a JSON object`);
		}
	}
	if (parsed === null || Array.isArray(parsed) || typeof parsed !== 'object') {
		throw new Error(`${fieldName} must be a JSON object`);
	}
	return parsed as IDataObject;
}

export function normalizeJsonOutput(value: unknown): IDataObject {
	return value !== null && !Array.isArray(value) && typeof value === 'object'
		? (value as IDataObject)
		: { data: value as never };
}
```

- [ ] **Step 4: Implement URL normalization and action-path confinement**

`normalizeBaseUrl` must parse with `new URL`, accept only `http:`/`https:`, reject username/password/query/hash, and return the URL without a trailing slash. `resolveActionUrl` must require a leading `/`, reject schemes, `//`, backslashes, malformed percent encodings, and literal/once-decoded/twice-decoded `.` or `..` path segments, then assert the resolved `origin` equals the normalized base origin.

```ts
export function resolveActionUrl(baseUrl: string, path: string): string {
	const base = new URL(normalizeBaseUrl(baseUrl, 'HTTP Actions URL'));
	if (!path.startsWith('/') || path.startsWith('//') || path.includes('\\')) {
		throw new Error('Path must be an absolute path on the configured HTTP Actions origin');
	}
	let decoded = path;
	for (let index = 0; index < 2; index += 1) {
		decoded = decodeURIComponent(decoded);
		if (decoded.split('/').some((segment) => segment === '.' || segment === '..')) {
			throw new Error('Path cannot contain traversal segments');
		}
	}
	const resolved = new URL(path, `${base.origin}/`);
	if (resolved.origin !== base.origin) throw new Error('Path must remain on the configured origin');
	return resolved.toString();
}
```
